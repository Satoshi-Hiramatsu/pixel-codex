# Pixel Codex

Codexの親エージェントとサブエージェントを、ピクセルオフィス上で可視化・操作するWindows向けデスクトップクライアントです。

バージョン **0.1.6**。変更の履歴は[更新履歴](#更新履歴)にまとめています。

## 現在のMVP

- Electronから`codex app-server`を標準入出力で起動
- App Serverのスレッド、ターン、ツール、承認、完了イベントを受信
- Phaser製オフィス内でエージェントの状態に応じて移動
- React製の出勤名簿、スタッフプロフィール、イベントログ（右カラムのタブで切り替え）
- AIの進捗報告・最終回答・質問を表示する会話パネル
- 各キャラクター上の、現在の作業や発言を示す吹き出し
- 統括責任者が引いたロードマップを、上から下へ流れる縦型の進行表として常時掲示
- トークン使用量を円に換算する発生経費メーターと、経理担当がまとめる会計報告
- AIの使用残量をゲームのHPゲージとして表示
- 作成・更新されたファイルと完了報告をまとめる、学校の黒板風の成果物ボード
- 成果物を既定アプリで直接開く機能と、作業フォルダを階層表示するプロジェクト図書館
- おすすめ人材の雇用、オリジナル人材作成、雇用チーム確認ができる社員名簿
- 作業ルールをRPGのスキルのように着脱できるスキルブック（グローバル／プロジェクト別、AI支援の新規作成、他プロジェクトからの取り込みと最適化）
- 作業フォルダのGitコミットとして記録するセーブ／ロード
- 指示への添付ファイル（ドロップ、Ctrl+Vでのスクリーンショット貼り付け）
- AIモデルと推論の強さの選択
- 企画一郎、絵描大好など、担当業務を連想できる固有のエージェント名
- WORKSPACE変更時のApp Server切断と、新しいフォルダへの自動再接続
- 正常に接続した作業フォルダの履歴保存と、次回起動時の最新フォルダ復元
- 作業フォルダ選択と親スレッド作成
- 新規タスク、実行中ターンへの追加指示、停止
- コマンド／ファイル変更の承認・拒否ダイアログ
- Codex未接続時のデモ表示

表示するのは状態、計画、ツール操作、変更、進捗です。モデルの内的思考は表示しません。

```text
├─────────────────────────────────────────────────────────────┤
│ ￥経費 ▓▓░ │ HP ▓▓▓▓▓▓ 100/100 │ ● いま全体が待っていること      │ ← HUD
├───────────────────────────────┬─────────┬───────────────────┤
│ DEV STUDIO 開発フロア          │ ROADMAP │ 名簿│ﾌﾟﾛﾌｨｰﾙ│会議│ﾛｸﾞ│ ← タブ
│                               │ 進行表  ├───────────────────┤
│                               │         │ 01 東葛大五郎   ● │
│        （フロア図）            │ ①受付   │    ロードマップ作成中│
│                               │  │      │ 02 企画一郎     ● │
│                               │ ②計画   │    要件を整理中     │
│                               │  │      │ 03 調辺探       ● │
│                               │ ③完了   │    仕様を調査中     │
├───────────────────────────────┤         ├───────────────────┤
│ NEW PROJECT [        ] 開始 → │ ひらく→ │ 追加指示 │ 停止    │
└───────────────────────────────┴─────────┴───────────────────┘
```

- **HUD** … 発生経費・HP・全体の待ち状態を1本の帯にまとめています。経費の枠を押すと明細のウィンドウが開き、お金の内訳・社員ごとのはたらき・HPの内訳がまとめて読めます。
- **開発フロア** … Phaser製のオフィス。社員をクリックすると右カラムがその人のプロフィールに切り替わります。
- **進行表** … 工程が上から下へ流れます。丸をつなぐ縦線は、完了ぶんが緑、作業中は途中まで金色に塗られます。
- **右カラム** … `名簿`／`プロフィール`／`会議・回答`／`ログ`のタブ。AIから質問が届くと自動で`会議・回答`へ切り替わり、裏に隠れているタブは橙色で点滅します。
- **出勤名簿** … 返事待ち → 作業中 → 待機 → 休憩 → 退勤の順に並びます。各行の2段目がその人のいまの作業です。

## 使い方

1. Pixel Codexを起動します。
2. 上部の`WORKSPACE`でCodexに作業させるフォルダを選びます。
3. `接続`を押します。
4. 自動検出できない場合は、右端の`…`から`codex.exe`を指定します。
5. `AIモデル`で使うモデルと推論の強さを選びます（`おまかせ`ならCodex CLI側の設定に従います）。
6. `NEW PROJECT`へ指示を書き、`開始`を押します。参考にしてほしいファイルは枠へドロップするか、Ctrl+Vでスクリーンショットを貼り付けます。
7. オフィスまたは`名簿`タブでエージェントを選び、`プロフィール`タブから追加指示や停止を行います。
8. `会議・回答`タブでAIのメッセージを確認し、質問が届いた場合は同じパネルから回答します。
9. `社員名簿`で利用するエージェントを雇用します。雇用した構成は次の新規プロジェクトから統括エージェントへ渡されます。
10. `スキル`で作業ルールを装備します。装備したスキルは次の指示から統括エージェントへ渡されます。
11. `成果物`の`開く`で完成したファイルを表示します。`図書館`では作業フォルダ内を移動し、任意のファイルやフォルダを開けます。
12. 区切りのいいところで`セーブ`を押します。作業フォルダのGitコミットとして記録されます。
13. `会計報告`でここまでにかかった費用の明細を確認します。
14. 上部の`WORKSPACE`を押すと最近接続したフォルダを再選択できます。不要な履歴は右側の`×`で削除できます。

接続中に`WORKSPACE`を変更すると、現在のApp Serverとスレッドを終了し、選択したフォルダで自動的に再接続します。

## セーブとロード

ゲームのセーブ／ロードを、作業フォルダのGitコミットとして実現しています。設計の要は「なにも失われないこと」です。

- **セーブ** … いまの状態をコミットします。変更が無くても記録できます。
- **ロード** … 先に自動セーブを取ってから、選んだセーブの中身を復元して**新しいコミットを積みます**。履歴を巻き戻さないので、ロードしたあとで戻したくなっても、直前のセーブをロードするだけで元に戻せます。

コミットはアプリ自身の名義（`Pixel Codex`）で作られるので、Gitのグローバル設定が済んでいないPCでもセーブが止まりません。PATH上に`git`が無い場合はセーブ機能だけが使えません。

## 経費とHP

かかった費用と、AIの残量をゲームの数値として見せています。

- **発生経費メーター** … Codexが報告するトークン数を、選んでいるモデルの単価で円に換算します。HUDの`￥`枠を押すと、入力・出力・キャッシュ利用ぶんの内訳、社員ごとのはたらき、他の契約だった場合の想定金額が出ます。表示は目安で、実際の請求はプランや割引で変わります。
- **会計報告** … 全員の手が止まると、経理担当が経理室でここまでの費用をまとめます。保存された報告は`会計報告`から後から読み返せます。発生経費を0円に戻しても、保存済みの報告は消えません。
- **HP** … AIの使用残量です。Codexが枠を教えてくれるプランのときだけ本物の数字が出ます。取得できない場合は`??`と表示されます。週や月の枠が複数あるときは、長いほうの枠がHPバーの脇に細いサブゲージとして並びます。内訳は明細ウィンドウの`HP（AI使用残量）`で確認できます。

## 添付ファイル

指示の欄と、プロフィールタブの追加指示の欄に添付できます。

- ファイルをドロップ、または`＋添付`から選択
- Ctrl+Vでクリップボードのスクリーンショットを貼り付け
- 1件20MBまで、1回8件まで
- 画像はモデルへ直接渡します。それ以外はパスを伝えて、Codexが自分で読みにいきます

貼り付けた画像は一時フォルダへ置かれ、アプリの終了時に削除されます。

## スキルブック

作業ルールを1件1ファイルのマークダウンで持ち、RPGの装備のように着脱します。装備中のスキルは、`社内ルール`の続きとして毎回の指示に添えられます。

1件のスキルは、スキル名・系統（コーディング系、企画系、範囲抑制系など）・効果（一覧に出る1行の要約）・詳細（そのままエージェントへ渡す指示文）でできています。

保存先は2か所です。

```text
%APPDATA%/Pixel Codex/
├─ skills/*.md   グローバルスキル（どのプロジェクトでも使える）
└─ skills.json   グローバルの装備状態

<作業フォルダ>/.pixel-codex/
├─ skills/*.md   プロジェクト専用スキル
└─ skills.json   このプロジェクトの装備状態
```

プロジェクト側は作業フォルダの中にあるので、セーブ（Gitコミット）に含まれ、フォルダごと配れば装備もそのまま移ります。手書きで置いた`.md`もそのまま読み込めます。

- **新規作成のAI支援** … 欲しいスキルを一言で書いて`AIに書いてもらう`を押すと、Codexがプロジェクトの中身を読んだうえで下書きを返します。内容は保存前に自由に直せます。
- **他プロジェクトから発掘** … 最近つないだ作業フォルダの`.pixel-codex/skills/`を探して一覧にします。`そのまま取り込む`はコピー、`最適化して取り込む`は、いまのプロジェクトの構成に合わせてCodexが書き直した下書きを作ります。

AI支援は、Codexへ接続していて作業フォルダを選んでいるときに使えます。この相談は使い捨てのスレッドで走るのでオフィスには誰も出社せず、かかった費用は会計報告に`スキル指南役`として並びます。

Codex CLIは同梱していません。端末にCodex CLIがインストールされ、ログイン済みであることが必要です。

## 構成

```text
src/
├─ codex/      App Serverプロセス・JSON-RPC通信・codex.exeの探索
├─ files/      添付ファイルの読み込み・一時保存
├─ game/       Phaserオフィス・エージェント表示・経路探索
├─ saves/      セーブ／ロード（作業フォルダのGit操作）
├─ skills/     スキルのファイル形式・読み書き
├─ stores/     Zustand状態管理・イベント変換
├─ App.tsx     React操作パネル
├─ AttachmentTray.tsx  添付ファイルの一覧・プレビュー
├─ SkillBook.tsx       スキルブック画面・装備状態
├─ costs.ts    トークン単価表・円換算
├─ models.ts   選択できるモデルと推論の強さ
├─ index.ts    Electronメインプロセス・限定IPC
└─ preload.ts  contextBridge API
```

レンダラーにはNode.jsや任意IPCを公開していません。`contextIsolation`とsandboxを有効にし、操作単位の限定APIのみをpreloadから公開しています。

## 更新履歴

### V0.1.6 — 画面レイアウトの全面見直し

開発フロア図が狭くなってきたので、画面全体の配り方を組み直しました。

- **状態表示を1本のHUDへ統合** … 縦に積み上がっていた「発生経費・HP」「進行表」「作業中」の3本の帯（合計222px）を、高さ46pxのHUD1本にまとめました。トークンの内訳や工程の詳細は、もともとある明細・進行表のウィンドウが受け持ちます。
- **進行表を縦型にしてフロア図の右へ** … 工程が上から下へ流れる縦長の柱になり、右カラムと同じ高さで常時見えます。横並びでは切れていた長い工程名も、折り返して全文が読めます。
- **作業看板を出勤名簿へ統合** … 「作業中」の帯と「出勤名簿」と「スタッフプロフィール」が同じ情報を3か所に出していたので、名簿の各行がその人のいまの作業を告げる形に一本化しました。並び順は返事待ち → 作業中 → 待機 → 休憩 → 退勤です。
- **右カラムをタブ化** … 縦に3段積んでいた`プロフィール`／`会議・回答`／`ログ`を、`名簿`を加えた4枚のタブにしました。質問が届くと`会議・回答`へ自動で切り替わり、裏のタブに手番があるときはタブ自体が点滅します。フロア図の社員をクリックすると`プロフィール`が開きます。
- 以上で、1440×900のウィンドウでフロア図の面積が**約2倍**（708×395 → 約930×600）になりました。

不具合の修正と、AIへの指示の改善もあわせて入れています。

- **経理担当がずっと「あなたの返事を待機中」と表示される不具合を修正** … 待ち受けの判定が、何も待っていないときの`undefined`と、Codexのスレッドを持たない経理担当の`threadId`（同じく`undefined`）を一致と見なしていました。
- **返事待ちのときは用件そのものを表示** … 「返事を待機中」だけでは画面を開き直すまで何を聞かれているのか分からないので、承認の見出しや質問の見出しを名簿の行に出すようにしました。
- **判断を求めるときの聞き方を統括責任者へ指示** … (a) 何について決めるのか（ファイル名・機能名まで）、(b) 選択肢とそれぞれを選んだ結果、(c) 推奨とその理由、の3点を必ず書かせます。「どうしますか？」のような対象の分からない質問と、自分で調べれば分かることの質問を禁じています。
- ウィンドウの最小幅を、レイアウトが必要とする幅（1240px）に合わせました。これより狭くすると右端が隠れていました。
