# Pixel Codex

Codexの親エージェントとサブエージェントを、ピクセルオフィス上で可視化・操作するWindows向けデスクトップクライアントです。

バージョン **0.3.3**。変更の履歴は[更新履歴](#更新履歴)にまとめています。

## 現在のMVP

- Electronから`codex app-server`を標準入出力で起動
- App Serverのスレッド、ターン、ツール、承認、完了イベントを受信
- Phaser製オフィス内でエージェントの状態に応じて移動
- React製の出勤名簿、スタッフプロフィール、イベントログ（右カラムのタブで切り替え）
- AIの進捗報告・最終回答・質問を表示する会話パネル
- 各キャラクター上の、現在の作業や発言を示す吹き出し
- 統括責任者が引いたロードマップを、上から下へ流れる縦型の進行表として常時掲示
- トークン使用量を円に換算する発生経費メーターと、経理担当がまとめる会計報告
- AIの使用残量をゲームのHPゲージとして表示
- 作成・更新されたファイルと完了報告をまとめる、学校の黒板風の成果物ボード
- 成果物を既定アプリで直接開く機能と、作業フォルダを階層表示するプロジェクト図書館
- おすすめ人材の雇用、オリジナル人材作成、雇用チーム確認ができる社員名簿
- 作業ルールをRPGのスキルのように着脱できるスキルブック（グローバル／プロジェクト別、AI支援の新規作成、他プロジェクトからの取り込みと最適化）
- 作業フォルダのGitコミットとして記録するセーブ／ロード
- 指示への添付ファイル（ドロップ、Ctrl+Vでのスクリーンショット貼り付け）
- AIモデルと推論の強さの選択
- 企画一郎、絵描大好など、担当業務を連想できる固有のエージェント名
- WORKSPACE変更時のApp Server切断と、新しいフォルダへの自動再接続
- 正常に接続した作業フォルダの履歴保存と、次回起動時の最新フォルダ復元
- 作業フォルダ選択と親スレッド作成
- 新規タスク、実行中ターンへの追加指示、停止
- コマンド／ファイル変更の承認・拒否ダイアログ
- Androidコンパニオンアプリとのケーブル不要な接続（QRまたは6桁コード）
- Androidからの新規・追加指示、承認の可否、質問への回答
- Androidからの要求に応じた画面プレビューの撮影と受け渡し
- Androidからの報告全文・進行表の取り寄せ
- 画面注釈アプリ「赤ペン先生」から、赤入れ画像と指示を同一PC内で受け取るキャプチャBridge
- 受け取った赤入れの確認帯（画像・指示・対象フォルダ・実行モードを確かめてから送る）
- 画面幅が足りないときに上部メニューを段階的に畳む表示（項目は減らさない）
- Codex未接続時のデモ表示

表示するのは状態、計画、ツール操作、変更、進捗です。モデルの内的思考は表示しません。

## 使い方

1. Pixel Codexを起動します。
2. 上部の`WORKSPACE`でCodexに作業させるフォルダを選びます。
3. `接続`を押します。
4. 自動検出できない場合は、右端の`…`から`codex.exe`を指定します。
5. `AIモデル`で使うモデルと推論の強さを選びます（`おまかせ`ならCodex CLI側の設定に従います）。
6. `NEW PROJECT`へ指示を書き、`開始`を押します。参考にしてほしいファイルは枠へドロップするか、Ctrl+Vでスクリーンショットを貼り付けます。
7. オフィスまたは`名簿`タブでエージェントを選び、`プロフィール`タブから追加指示や停止を行います。
8. `会議・回答`タブでAIのメッセージを確認し、質問が届いた場合は同じパネルから回答します。
9. `社員名簿`で利用するエージェントを雇用します。雇用した構成は次の新規プロジェクトから統括エージェントへ渡されます。
10. `スキル`で作業ルールを装備します。装備したスキルは次の指示から統括エージェントへ渡されます。
11. `成果物`の`開く`で完成したファイルを表示します。`図書館`では作業フォルダ内を移動し、任意のファイルやフォルダを開けます。
12. 区切りのいいところで`セーブ`を押します。作業フォルダのGitコミットとして記録されます。
13. `会計報告`でここまでにかかった費用の明細を確認します。
14. 上部の`WORKSPACE`を押すと最近接続したフォルダを再選択できます。不要な履歴は右側の`×`で削除できます。

接続中に`WORKSPACE`を変更すると、現在のApp Serverとスレッドを終了し、選択したフォルダで自動的に再接続します。

## セーブとロード

ゲームのセーブ／ロードを、作業フォルダのGitコミットとして実現しています。設計の要は「なにも失われないこと」です。

- **セーブ** … いまの状態をコミットします。変更が無くても記録できます。
- **ロード** … 先に自動セーブを取ってから、選んだセーブの中身を復元して**新しいコミットを積みます**。履歴を巻き戻さないので、ロードしたあとで戻したくなっても、直前のセーブをロードするだけで元に戻せます。

コミットはアプリ自身の名義（`Pixel Codex`）で作られるので、Gitのグローバル設定が済んでいないPCでもセーブが止まりません。PATH上に`git`が無い場合はセーブ機能だけが使えません。

## 経費とHP

かかった費用と、AIの残量をゲームの数値として見せています。

- **発生経費メーター** … Codexが報告するトークン数を、選んでいるモデルの単価で円に換算します。HUDの`￥`枠を押すと、入力・出力・キャッシュ利用ぶんの内訳、社員ごとのはたらき、他の契約だった場合の想定金額が出ます。表示は目安で、実際の請求はプランや割引で変わります。
- **会計報告** … 全員の手が止まると、経理担当が経理室でここまでの費用をまとめます。保存された報告は`会計報告`から後から読み返せます。発生経費を0円に戻しても、保存済みの報告は消えません。
- **HP** … AIの使用残量です。Codexが枠を教えてくれるプランのときだけ本物の数字が出ます。取得できない場合は`??`と表示されます。週や月の枠が複数あるときは、長いほうの枠がHPバーの脇に細いサブゲージとして並びます。内訳は明細ウィンドウの`HP（AI使用残量）`で確認できます。

## 添付ファイル

指示の欄と、プロフィールタブの追加指示の欄に添付できます。

- ファイルをドロップ、または`＋添付`から選択
- Ctrl+Vでクリップボードのスクリーンショットを貼り付け
- 1件20MBまで、1回8件まで
- 画像はモデルへ直接渡します。それ以外はパスを伝えて、Codexが自分で読みにいきます

貼り付けた画像は一時フォルダへ置かれ、アプリの終了時に削除されます。

## スキルブック

作業ルールを1件1ファイルのマークダウンで持ち、RPGの装備のように着脱します。装備中のスキルは、`社内ルール`の続きとして毎回の指示に添えられます。

1件のスキルは、スキル名・系統（コーディング系、企画系、範囲抑制系など）・効果（一覧に出る1行の要約）・詳細（そのままエージェントへ渡す指示文）でできています。

保存先は2か所です。

```text
%APPDATA%/Pixel Codex/
├─ skills/*.md   グローバルスキル（どのプロジェクトでも使える）
└─ skills.json   グローバルの装備状態

<作業フォルダ>/.pixel-codex/
├─ skills/*.md   プロジェクト専用スキル
└─ skills.json   このプロジェクトの装備状態
```

プロジェクト側は作業フォルダの中にあるので、セーブ（Gitコミット）に含まれ、フォルダごと配れば装備もそのまま移ります。手書きで置いた`.md`もそのまま読み込めます。

- **新規作成のAI支援** … 欲しいスキルを一言で書いて`AIに書いてもらう`を押すと、Codexがプロジェクトの中身を読んだうえで下書きを返します。内容は保存前に自由に直せます。
- **他プロジェクトから発掘** … 最近つないだ作業フォルダの`.pixel-codex/skills/`を探して一覧にします。`そのまま取り込む`はコピー、`最適化して取り込む`は、いまのプロジェクトの構成に合わせてCodexが書き直した下書きを作ります。

AI支援は、Codexへ接続していて作業フォルダを選んでいるときに使えます。この相談は使い捨てのスレッドで走るのでオフィスには誰も出社せず、かかった費用は会計報告に`スキル指南役`として並びます。

Codex CLIは同梱していません。端末にCodex CLIがインストールされ、ログイン済みであることが必要です。

## 赤ペン先生からの受け取り（キャプチャBridge）

画面注釈アプリ「赤ペン先生」（[Satoshi-Hiramatsu/gInk](https://github.com/Satoshi-Hiramatsu/gInk)・V1.4.5以降）で画面に赤入れし、その画像と指示をPixel Codexへ渡せます。ネットワークは通りません。**同じPCの同じ利用者のあいだだけ**で完結します。

```text
赤ペン先生で赤入れ → Codexへ送る
  → Pixel Codexが画像を自分の管理下へ写して受領
  → 指示欄の上に確認帯が出る（画像・指示・対象フォルダ・実行モード）
  → 利用者が「開始 →」を押して初めてCodexが動く
  → 完了・失敗を赤ペン先生へ返す
```

**受け取っただけではCodexは動きません。** 人が画面で内容を確かめる工程を必ず挟みます。

### 使い方

1. Pixel Codexを起動します（`%APPDATA%\Pixel Codex\bridge.json` が作られます）
2. 赤ペン先生の`gInk\bin\agent.ini`で`Agent_Backend = Auto`にします
3. `Ctrl + Alt + G`で赤入れし、`I`キー（またはツールバーのCodexボタン）で送信画面を開きます
4. 対象リポジトリは**Pixel Codexの作業フォルダと同じ**にしてください。実際にCodexが読み書きするのはPixel Codex側の作業フォルダです

`Auto`はPixel Codexが起動していればそちらへ渡し、いなければ赤ペン先生の内蔵Codexで実行します。`PixelCodex`を明示した場合は、使えなくても無断で別の宛先へ送りません。

通信室の`07 赤ペン先生からの受け取り`で受け取り口を開閉できます。既定は有効です。

### 同一利用者に限る仕組み

名前付きパイプにはNode.jsからACLを設定できないため、「既定で他の利用者から見えないはず」という推測には頼っていません。

- 待ち合わせ場所（パイプ名）と合言葉を、利用者のプロファイル配下`%APPDATA%\Pixel Codex\bridge.json`にだけ書きます。他の利用者はNTFSのACLでこれを読めません
- パイプ名自体を、その控えからしか知りえない乱数にしています。名前を知らなければ接続を試すこともできません
- 接続後、合言葉そのものは一度も流しません。nonceのHMACで双方向に確認します。サーバー側が先に証明するため、パイプ名を先取りした偽物へ指示や画像の場所を渡すことはありません

受け取り時は、プロトコル版数、1行の長さ、指示の長さ、画像の大きさ、絶対パスであること、UNCでないこと、PNGの署名を先頭8バイトで実際に確認します。ログには種別と長さだけを残し、指示の全文や画像の内容、利用者名を含む絶対パスは出しません。

### 検証

```powershell
npm run bridge:verify   # プロトコルとパイプ往復の自動テスト（27件）
npm run bridge:send     # 赤ペン先生の代役。動いているPixel Codexへ試しに送る
```

`bridge:send`は赤ペン先生を起動せずにPixel Codex側だけを確かめるための道具です。`--mode Discuss`、`--cwd <path>`、`--hold`、`--drop-after-accept`などを指定できます。

設計と実装の判断は[docs/PIXEL_CODEX_BRIDGE_PLAN.md](https://github.com/Satoshi-Hiramatsu/gInk/blob/main/docs/PIXEL_CODEX_BRIDGE_PLAN.md)、実機確認の手順は[docs/PIXEL_CODEX_BRIDGE_CHECKLIST.md](https://github.com/Satoshi-Hiramatsu/gInk/blob/main/docs/PIXEL_CODEX_BRIDGE_CHECKLIST.md)にあります（いずれも赤ペン先生リポジトリ内）。

## Android連携（開発中）

通信室からRelay接続と通知方針を設定できます。Androidアプリのソースは[`android-companion`](android-companion)にあります。

Androidからできること：

- PCの状態、統括責任者、最新メッセージの確認
- 新規指示と追加指示の送信（作業中なら自動でQueueへ）
- 承認の可否と、Codexからの質問への回答（**PC側で明示的に許可した場合のみ**）
- 作りかけの画面を撮って見る（同上）
- 報告の全文と進行表の確認

### つなぎ方

同じネットワークにPCと端末があれば、ケーブルは使いません。

1. 通信室の`ケーブルなしでペアリング`を押すと、PCのアドレス・6桁コード・QRが出ます。
2. Androidアプリの`通信設定`タブで`QRで読み取る`を押して読み取ります（手入力も可）。
3. `PCオンライン`になれば完了です。

コードは3分で失効し、5回まちがえるとその場で受付を終了します。一度成功すればRelayのトークンとポートはPCに保存されるので、**次回からはアプリを開くだけで再接続**します。

PCのIPアドレスが変わっても、端末が同じネットワークにいれば自動で探し直します。手動で探す場合は`通信設定`タブの`PCを探し直す`を押します。ペアリングのやり直しは不要です。

APKをまだ入れていない端末や、うまくいかない場合の手段として、USB経由の`USB実機テストを開始`と`Wi-Fi実機テストを開始（USBで初期設定）`も残しています。

### スマートフォンからの承認

通信室の`承認の可否と質問への回答をスマートフォンから行う`は**既定でオフ**です。オンにすると、コマンド実行やファイル変更の許可を手元の端末から出せるようになります。

- 承認内容（コマンド、作業場所、リスク）が端末にも表示されます
- `機微情報を隠す`が有効な間は、パスとトークンを伏せて送ります
- 秘密の入力を含む質問は端末へ送らず、PCでのみ回答できます
- PCで先に処理済みの承認に端末から答えても拒否されます

### スマートフォンから見た目を確認する

Webサイトやアプリを作っている途中、いまどう見えているかを手元の端末から確かめられます。通信室の`スマートフォンからの要求で画面を撮って送る`は**既定でオフ**です。

撮れる対象は3種類です。

| 対象 | 登録 |
| --- | --- |
| 開発サーバーのURL | 通信室の`プレビューURL`に`http://localhost:3000`などを追加します（8件まで） |
| PC上のウィンドウ | 登録不要。開発中のアプリ、ブラウザ、Pixel Codex自身が候補に並びます |
| 作業フォルダのHTML | 登録不要。生成されたHTMLが自動で候補に加わります |

端末側はアプリの`見た目`タブで対象を選ぶだけです。URLとHTMLは`スマホ幅`（390×844）と`PC幅`（1280×800）で撮り分けられます。

- **要求したときだけ**撮ります。作業が終わっても勝手には届きません
- 1枚は幅1080pxのJPEGへ落とすため50〜150KB程度です
- 端末が送れるのはPCが登録した一覧のIDだけで、URLやパスは受け取りません
- 画像はRelayの`GET /blob/<id>?token=`から取ります。IDは推測できない値で、10分で実ファイルごと消えます
- 撮影はPCに負荷がかかるため、連打しても5秒に1回までです
- 最小化されているウィンドウは撮れません

見せたくないものが映る画面は登録しないでください。撮った画像はそのまま端末に表示されます。

### 外出先から見返す（Google Drive・任意）

内蔵Relayは同じWi-Fi内でしか届きません。外出先でも見返したい画像は、端末の`Driveへ預ける`ボタンでGoogle Driveへ上げられます。**押したときだけ**上がるので、撮ったものが勝手にGoogleへ出ることはありません。

準備は初回だけです。

1. [Google Cloud Console](https://console.cloud.google.com/)でプロジェクトを作る
2. `APIとサービス` → `ライブラリ`で **Google Drive API** を有効にする
3. `OAuth同意画面`を作り、自分のアカウントをテストユーザーに追加する
4. `認証情報` → `OAuthクライアントID`を作る。**種類は`デスクトップアプリ`**
5. 発行されたクライアントIDとシークレットを通信室の`Google Drive`欄へ入力し、`認証情報を保存` → `Googleと接続`

- 求める権限は`drive.file`だけです。**このアプリが作ったファイル以外のDriveの中身は読めません**
- 画像はマイドライブの`Pixel Codex Previews`フォルダに入ります。削除は手動です
- リンクを共有設定にはしません。端末側で**同じGoogleアカウントにサインイン**している必要があります
- クライアントシークレットと更新用トークンはOSの暗号化領域（`safeStorage`）に保存し、画面には戻しません
- 認証はループバック（`127.0.0.1`）で受けます。PKCEを使うため、外から叩ける口は開きません

### 開発用Relayを単独で起動する場合

```powershell
$env:PIXEL_CODEX_RELAY_TOKEN='replace-with-a-long-random-token'
npm.cmd run relay:dev
```

### 制限

内蔵Relayは同一ネットワーク内での平文`ws://`接続です。外出先から使うための中継サービス、端末鍵、FCM通知は未実装です。開発用URLトークンを本番認証として使用しないでください。

画面プレビューも同じRelayを通るため、**同じWi-Fiにいる間だけ**届きます。外出先から見返す手段としてGoogle Driveへの受け渡しを用意していますが、こちらは利用者自身のGoogle Cloudプロジェクトが必要です。

Windows Defender Firewallが確認を表示した場合は、プライベートネットワークを許可してください。誤って拒否するとブロック規則が残り、以後の接続がすべて失敗します。復旧手順は[android-companion/README.md](android-companion/README.md)にあります。

- **同一利用者に限る仕組みを、推測に頼らず用意** … 待ち合わせ場所と合言葉を利用者のプロファイル配下にだけ置き、合言葉そのものは通信路へ流さずnonceのHMACで双方向に確認します

**上部メニューが画面幅に収まらない問題を修正しました。**

解像度や表示スケールによっては、`AIモデル`から右が画面の外へ出て押せませんでした。上部メニューの2列が中身より小さくならない指定になっており、必要な約1480pxを確保しようとして帯ごとはみ出していたためです。ウィンドウの最小幅は1240pxなので、最小幅では必ず切れていました。

- **押せる場所と並び順は変わりません** … アイコンだけになっても位置は同じで、`title`で名前を確認できます。人数や件数のバッジも残します

### V0.3.2 — QRコードが読み取れない不具合の修正

外部Relay用のURLのQRが、カメラで読み取れなくなっていました。

QRの大きさを`264px`と決め打ちしていたことが原因です。URLのQRは余白を含めて57マスあり、264を57で割ると1マス4.63ピクセルという半端な値になります。マスの大きさが4pxと5pxで不揃いになり、`image-rendering: pixelated`と相まって格子が歪んでいました。実測では**1790マス**が正方形になっていませんでした。ペアリング用のQRは1マス7.14pxと大きく誤差を吸収できていたため、URLのQRだけが読めない状態でした。

- **全体の幅ではなく1マスのピクセル数で指定** … マスの数で割り切れる整数にしたので、どのマスも同じ大きさになります。修正後は歪んだマスが0になりました
- **静穏帯を規格どおり4マスに** … 2マスしか取っておらず、カメラが枠を掴みにくい状態でした
- **長いQRは誤り訂正を下げる** … 画面に出すだけで汚れも折れもないため、URLのQRは訂正レベルをLにしました。マス数が53から49に減り、1マスは4.63pxから6pxへ約30%大きくなります

### V0.3.1 — スマートフォンでの読みやすさ

外出先で開いたときに、知りたいことへすぐ届くようにしました。

### V0.3.0 — スマートフォンから成果物の見た目を確認する

これまで外出先から分かるのは文字だけでした。作りかけのサイトが今どう見えているかを、手元の端末から確かめられるようにしました。

- **スマートフォンから画面を要求** … Androidアプリに`見た目`タブを追加しました。対象を選んで押すとPCがその場で撮影し、画像が端末に表示されます。**要求したときだけ**動くので、待機中や作業中の通信量は従来のままです。
- **3種類の対象** … 通信室に登録した開発サーバーのURL、PC上で開いているウィンドウ（開発中のアプリやブラウザ、Pixel Codex自身）、作業フォルダに生成されたHTMLです。ウィンドウとHTMLは登録不要で候補に並びます。
- **スマホ幅とPC幅** … URLとHTMLは390×844と1280×800で撮り分けられます。レスポンシブの確認をそのまま手元で行えます。
- **画像はHTTPで受け渡し** … Relayは1通16KBまででバイナリを扱えないため、画像をWebSocketに載せると1枚が100通以上に割れてしまいます。代わりにRelayへ`GET /blob/<id>?token=`を追加しました。宛先は推測できないIDで、10分で実ファイルごと消えます。
- **端末は対象を選ぶだけ** … 端末が送れるのはPCが登録した一覧のIDだけで、URLやパスは受け取りません。撮った画像は幅1080pxのJPEGへ落とすため1枚50〜150KBです。
- **既定はオフ** … 承認機能と同じく、通信室で明示的に許可したときだけ有効になります。撮影の連打はPCが重くなるため5秒に1回までに制限しています。
- **外出先ではGoogle Driveへ** … 内蔵Relayは同じWi-Fi内でしか届きません。後で見返したい画像だけ、端末の`Driveへ預ける`から上げられます。押したときだけ上がるので、撮ったものが勝手にGoogleへ出ることはありません。求める権限は`drive.file`のみで、このアプリが作ったファイル以外のDriveの中身は読めません。開発者の資格情報を配布物に埋め込まず、利用者が自分のGoogle Cloudプロジェクトで作ったOAuthクライアントを通信室へ登録する方式です。シークレットと更新用トークンはOSの暗号化領域に保存します。

### V0.2.1 — 完全ワイヤレス接続と、スマートフォンからの承認

V0.2.0では初回設定にUSBケーブルが必要でした。ここを外し、外に持ち出せる形にしました。

- **ケーブル不要のペアリング** … 通信室でPCのアドレスと6桁コードを表示し、Androidから入力すればトークンを受け取って接続します。コードは3分で失効し、5回失敗でその場で受付終了。比較は`timingSafeEqual`で行います。
- **QRコードで一発接続** … 上記の内容をQRにして表示します。Android側はカメラで読み取るだけです。外部Relayを使う設定もQRで渡せます。
- **RelayのポートとトークンをPCに保存** … ポートは57170から順に空きを探し、トークンは`%APPDATA%`へ保存します。一度ペアリングすれば、PCを再起動しても端末は自動で再接続します。
- **PCのIP変更に追従** … ノートPCでネットワークが変わってもアドレスだけの問題なので、LAN内から`/health`を頼りにPCを探し直します。前回PCがいたサブネットと端末自身のサブネットの両方を見るため、両者が別セグメントに置かれる構成でも復帰します。探索中にトークンは送りません。
- **承認と質問への回答をスマートフォンから** … 通信室のトグル（既定オフ）を入れると、承認カードと質問カードが端末に出て、その場で可否と回答を返せます。`機微情報を隠す`設定に従ってパスとトークンを伏せ、秘密の入力を含む質問は端末へ送りません。
- **Androidアプリの画面を分離** … `Codex`（状態・指示・承認）と`通信設定`（ペアリング・接続）の2タブにしました。`切断`と`前回の設定で再接続`も追加しています。
- **受信メッセージの検査を拡張** … `RemoteCommandGuard`が`approval.respond`と`question.respond`にも対応しました。型、送信先PC、`messageId`の重複、時刻のずれ（±2分）に加え、可否は`accept`／`decline`のみ、回答は12件・1000文字までに制限します。

不具合の修正：

- **Wi-Fi実機テストのIPCハンドラが登録されていなかった問題を修正**（V0.2.0で`remote:start-wireless-test`が未登録でした）
- **接続用QRがPC自身のループバックアドレスを配っていた問題を修正** … `ws://127.0.0.1:...`は端末から見ると端末自身を指すため接続できませんでした。QRを作る前にLANアドレスへ書き換え、端末側でも読み取り時に弾きます。
